## Test limits

The review included real low-score, mixed-score, and high-score responses, concurrent/repeated request rejection, completed-response reloads, and language switching. A low-score response that implied the participant was “doing well” was identified during testing; the prompt now explicitly prohibits that inference and the response parser rejects this and other explicit diagnostic, prescription, and predictive claims. The parser is a conservative extra check, not a complete clinical safety classifier. Rejected responses are not shown and are not automatically regenerated. Public copy uses plain labels; processing and storage details remain available through short privacy disclosures.

Technical testing is not clinical or research-ethics validation. Translation approval, study consent/retention procedures, and clinical interpretation remain the research team's responsibility as required by the guide. Real support-provider availability must be checked before participant recruitment. Gemini responses are model-generated and can contain mistakes; they are not a diagnosis or a replacement for a qualified professional.

Test the public flow without researcher opt-in for synthetic UI data. A completed local reflection is reusable; End session explicitly clears it. An interrupted model request is not retried, preserving the requested one-attempt limit. Only a new screening session gets a new allowance.
